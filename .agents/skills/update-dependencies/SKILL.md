# Update Dependencies

Update AuthGlow dependencies in a controlled backend-first sequence. Do not
commit changes automatically.

## Rules

- Run the backend phase before touching the frontend.
- Stop immediately if a dependency command or validation command fails.
- Never reset, checkout, clean, stash, or overwrite unrelated worktree changes.
- Preserve user changes and report them separately from dependency changes.
- Use the exact backend commands below.
- Frontend updates must include major versions, not only versions allowed by
  the existing semver ranges.
- Do not use `npm audit fix` as a substitute for updating dependencies.
- At the end, show the changed files and validation results.

## Preflight

1. Confirm the repository root and the `backend/` and `frontend/`
   directories.
2. Confirm `uv`, `npm`, and `npx` are available.
3. Run `git status --short` and record the initial worktree state.
4. Do not modify files outside the dependency manifests, lock files, or files
   generated by the package managers unless a validation fix is explicitly
   requested.

## Backend First

Run these commands from `backend/`, in order:

```bash
uv pip compile requirements.in -o requirements.txt --upgrade
uv pip install --upgrade -r requirements.txt
```

After installation, validate the backend:

```bash
ruff check authglow/
mypy authglow/
pytest -q --tb=line -n auto
```

If any backend command fails, stop. Report the failure and do not update the
frontend.

## Frontend

Run these commands from `frontend/`, in order:

```bash
npx --yes npm-check-updates -u
npm install
```

`npm-check-updates` is intentional: `npm update` usually stays within the
existing semver ranges and therefore does not guarantee latest major versions.

After installation, validate the frontend:

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

If a frontend command fails, stop and report the failure without attempting
automatic compatibility fixes.

## Final Report

Run `git status --short` and `git diff --stat`. Report:

- Backend packages changed in `requirements.txt`.
- Frontend packages changed in `package.json` and `package-lock.json`.
- Validation commands that passed.
- The first failing command, if any, with its relevant error summary.
- Any unrelated pre-existing worktree changes.

Do not create a commit unless the user explicitly asks for one.
